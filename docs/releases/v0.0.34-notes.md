Ovim 0.0.34 improves browser live sync, Alacritty popup handling, and local builds.

- Float Ovim's Alacritty popup in AeroSpace, including when macOS does not expose the field's coordinates. Regular terminal windows keep their layout.
- Reuse the running Alacritty app for positioned and prewarmed popups. Opening an editor no longer starts a duplicate Alacritty process after successful IPC.
- Support repeated live edits inside Reddit chat's nested shadow fields, including multiline text without sending Enter to the chat composer.
- Hide temporary browser replacement selections and the caret during sync. Appended text uses the existing draft instead of selecting it all again. Controlled editors retain trusted keyboard input.
- Move browser sync off Neovim's RPC thread. Skip outdated queued snapshots and finish the last update before the session closes.
- Restore bmux field coordinates when accessibility geometry is unavailable. Resolve Node correctly when Ovim starts from Finder.
- Keep permission settings visible and request Input Monitoring explicitly. Local packaging uses a stable Developer ID signature and rejects ad-hoc replacements. Keep the same signing identity, bundle ID, and installation path across builds.
- Start release builds when an approved draft is published. Verify release downloads and Homebrew checks before updating the tap.

Read the [AeroSpace setup guide](https://vim.tonis.dev/articles/ovim-aerospace) and [local-build permission instructions](https://github.com/tonisives/ovim#keep-permissions-across-local-builds).

Existing limitation: plain contenteditable fields can report an extra blank line through Chromium's `innerText`. This occurs in both 0.0.33 and this candidate.
